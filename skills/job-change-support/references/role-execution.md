# 役割の実行の原本（role-execution）

専門の役割へ作業を委ねるときの、ハーネス別の実行手順と、起動する数の判断を定める原本である。全サブスキルの「役割の実行（ハーネス別）」がこのファイルを参照する。

役割の内容そのもの（役割プロンプト）は各サブスキルの `references/roles/` にあり、どの作業をどの役割へ委ねるかは各サブスキルの SKILL.md にある。ここには、その役割をどう動かすかだけを置き、参照元へ複製しない。

## サブエージェントを起動できるハーネス（Claude Code）

各 Step の記述どおり、SKILL.md の表にあるエージェント名を Agent ツールで起動し、指示書を渡す。エージェント定義はリポジトリの `agents/` にあり、各サブスキルの `references/roles/` のコピーである。

## サブエージェントを起動できないハーネス（Codex ほか）

各 Step の「エージェントを起動する」を「役割プロンプトを読み、その役割として自分で実行する」と読み替える。手順は次のとおり。

1. SKILL.md の表にある役割プロンプトを Read で読む。
2. Step に書かれた指示書の項目を、そのまま自分への指示として扱う。
3. 役割プロンプトの「扱ってよい入力」のルールを守る。Web 送信手段を持たない役割として書かれている場合、その作業中は Web 検索・fetch を使わない。
4. 成果物の形式・検証・合否ゲートは、ハーネスによらず同一である。

## 起動する数

委譲は小さな作業でも費用が増える。1つの役割で足りるときは1つだけ起動し、同じ作業を複数の役割へ重ねて任せない。自分が作った成果物を確かめさせるためにエージェントを起動しない。作成した本人の文脈で読み直しても、その文脈が判定に持ち込まれるだけである。形式と規則の確認は検証スクリプトが担う。

例外は、次の「作成と監査の分離」に当たる4スキルの監査である。この4スキルでは、機械的な検証の PASS を確認したうえで監査担当を必ず起動する。

## 作成と監査の分離

`job-change-profile`・`job-change-self-analysis`・`job-change-company-research`・`job-change-documents` は、作成する役割と監査する役割を分けている。監査担当には作成時の判断理由を渡さず、成果物と仕様だけを見て判定させる。作成側の文脈を持たないことが判定の条件であり、同じ文脈で読み直すことでは代えられない。この費用は、誇張・創作・仕様との食い違いを作成側の意図から独立に見つけるために払う。

サブエージェントを使えないハーネスでは、同一の文脈で作成と監査の両方を担うため、この独立性が下がる。その場合、監査の段階では作成時の判断理由・迷った箇所・書き換えの経緯を一切参照せず、成果物と原本（`references/` の仕様）だけを見て判定する。判定を終えるまで、作成側の意図を補って読まない。
