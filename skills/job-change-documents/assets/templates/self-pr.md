# 自己PRテンプレート（結論→証明→貢献）

## 使い方

- 職務経歴書または履歴書の自己PR欄へ書く場合に選ぶ。どちらの書類でも構成は同じである。
- 分量は300字程度、最長400字（出典 M7）。職務経歴書の自己PR欄として書く場合の目安は200〜400字（出典 S8）であり、300字程度に収めれば双方に収まる。
- 強みは1つに絞る。多くても3つまでとする（出典 M7）。数を増やすほど1つあたりの証明が薄くなる。
- 3段は続けて1つの文章として書き、見出しを成果物に残さない。構成の名前（PREP・STAR など）を成果物にも指示にも書かない。応募先へ向けた文章であるため敬体で書く。
- `{profile.…}` は profile.json のフィールド、`{…}` は求人票・企業研究など profile.json 以外の入力を指す。`<!-- -->` は作成担当への指針であり、成果物には残さない。
- 抽象的な自己評価で終えない。強みは行動と結果で裏づける。

## 構成

```markdown
<!-- 必須。3段を続けて1つの文章として書く。以下の3つの見出しは構成を示すためのものであり、成果物には残さない。 -->

【結論（強み）】
<!-- 必須。{profile.strengths[]} から1つ、多くて3つ選び、冒頭で言い切る（出典 M7）。{求人要件} に最も近いものを先頭に置く。{career-private/self_analysis.json} がある場合は、行動証拠または他者証言に対応づけられた strengths を優先して選ぶ。strengths が空なら、achievements[].description から繰り返し現れる行動を強みとして立てる。 -->

【証明（行動と結果）】
<!-- 必須。強みを裏づける実績を {profile.career_history[].achievements[]} から1〜2件選び、何をしたか（行動）と、どうなったか（結果）の順で書く。数値は {profile.career_history[].achievements[].metric} を一字一句そのまま引く。丸め・水増しをしない。metric が null の実績を選んだ場合は数値を付けず、担当範囲・役割・工夫を事実で書く。チームの成果ではなく本人の貢献を書く。「大規模」「全社」「主導」などの言葉は profile.json が裏づける範囲に限る。 -->

【貢献】
<!-- 必須。同じ行動を応募先で何にどう活かすかを1〜2文で述べる。{求人要件} に対応づける。求人票が無い場合は {company_research} の事業内容に対応づけ、いずれも無ければ職種一般の課題に対応づける。「頑張ります」だけの意欲で終わらせない。 -->
```

## 記入例

```markdown
大規模移行を計画から完遂まで主導した実行力が強みです。架空リテールテック株式会社では、2022年4月から2024年3月まで決済基盤の技術リードを務め、モノリスからマイクロサービスへの段階移行を主導しました。その結果、ピーク時 API 応答時間を平均820msから310msへ短縮（約62%改善）しています。並行してリリースプロセスの CI/CD を整備し、デプロイ頻度を週1回から日次へ（約5倍）、障害回復時間を平均4時間から40分へ短縮しています。既存システムの改善を、計測できる指標に置き換えて進めます。この進め方で貢献いたします。
```

<!-- 記入例の強みは profile.json の strengths[0] をそのまま用い、証明は同じ会社の achievements 2件の metric を原文のまま引いている。文字数は約260字である。 -->
