# 職務経歴書テンプレート（ITエンジニア式）

## 使い方

- 技術職に選ぶ。テクニカルスキルの節が独立して増え、職務経歴をプロジェクト単位で書く点が他の3形式と違う（出典 S7・S11・S12・S15）。
- プロジェクトは1件ずつ、期間・案件・体制と役割・担当・成果・使用技術で書く（出典 S12・S15）。並べ方は新しい順とする。
- 分量は、社会人経験7年程度まで A4 1〜2枚、それ以上は2〜3枚（出典 S8）。職務要約は200〜300字・3〜5行（出典 S2・S8）、自己PRは200〜400字（出典 S8）。
- `{profile.…}` は profile.json のフィールド、`{…}` は求人票・企業研究・作成日など profile.json 以外の入力を指す。`<!-- -->` は作成担当への指針であり、成果物には残さない。
- 値の無い項目を行ごと省くか「特になし」と書くかは、節ごとの `<!-- -->` に従う。
- 応募先が様式を指定した場合は、このテンプレートを使わず指定の様式に従う。

## 構成

```markdown
# 職務経歴書
<!-- 必須。表題を先頭に置き、続く2行の作成日と氏名を右寄せにする（出典 S2・S3・S6・S8）（Markdown では位置指定を付けず、Word・PDF へ書き出すときに整える）。氏名は profile.json に無いため利用者に確認する。日付は提出日とし、西暦・和暦は書類全体で統一する。 -->

{作成日}現在
氏名: {氏名}

## 職務要約
<!-- 必須。{profile.summary} を核に、{profile.basic.years_of_experience}・{profile.basic.current_role} と、主に扱ってきた技術領域を200〜300字でまとめる。{求人要件} の技術との接点を先に述べる。{profile.career_gaps[]} がある場合、その説明はここか自己PRで用いる。節は省かない。 -->

## 職務経歴
<!-- 必須。{profile.career_history[].achievements[].project} と {profile.career_history[].responsibilities[]} からプロジェクトを立て、開始年月の新しい順に並べる。project が無い実績は、responsibilities の記述を案件名として用いる。1つの実績を複数のプロジェクトへ重複して載せない。 -->

### {案件名}（{profile.career_history[].achievements[].period} または {profile.career_history[].period}）

- 在籍企業: {profile.career_history[].company}
- 体制と役割: {profile.career_history[].role}、{responsibilities に記載のある体制}
<!-- 体制（チーム人数など）は responsibilities に記載がある場合だけ書く。記載が無ければ役割だけを書き、人数を推測しない。 -->
- 担当
  - {profile.career_history[].responsibilities[]}
- 成果
  - {profile.career_history[].achievements[].description}: {profile.career_history[].achievements[].metric}
<!-- metric は一字一句そのまま引く。丸め・水増しをしない。metric が null の実績には数値を付けず、担当範囲・役割・工夫を事実で書く。achievements が空の案件は「成果」の見出しごと省く。 -->
- 使用技術: {responsibilities に記載のある言語・基盤}
<!-- そのプロジェクトで使ったと profile.json が示す技術だけを書く。{profile.skills.technical[]} のうちプロジェクトとの対応が profile.json から読めないものは、ここではなくテクニカルスキルの節にだけ載せる。 -->

## テクニカルスキル
<!-- 必須（ITエンジニア式のみ。出典 S7・S11・S12）。{profile.skills.technical[]} を、言語・フレームワーク／クラウドと基盤／データベース／その他に分けて並べる。経験年数・習熟度は profile.json に無いため書かない。technical が空なら、プロファイルの職歴と実績の深掘りへ戻す。 -->

- 使用言語: {profile.skills.technical[]}
- 環境・基盤: {profile.skills.technical[]}
- データベース: {profile.skills.technical[]}

## 活かせる経験・知識・スキル
<!-- 推奨。{profile.skills.business[]}・{profile.skills.portable[].skill} から、{求人要件} に対応するものだけを選ぶ。テクニカルスキルの節と同じ項目を繰り返さない。対応するものが無ければ節ごと省く。 -->

## 資格・免許
<!-- 必須。{profile.skills.certifications[]} を並べる。取得年月は profile.json に無いため、利用者が示した場合だけ添える。certifications が空なら「特になし」と書く。節は省かない。 -->

## 自己PR
<!-- 必須。{profile.strengths[]} から強みを1つ、多くて3つ選び、結論→証明→貢献の順で200〜400字（出典 S8）。証明には achievements[].metric を引く。詳しい構成は self-pr.md にある。節は省かない。 -->

## 志望動機・転職理由
<!-- 任意。応募先が求めた場合だけ置く。{profile.job_change_axis.reasons[]} と {company_research} の claim を素材に、200〜300字を目安とする。企業研究が無ければ企業固有の内容は書けないため、節ごと省く。詳しい構成は motivation-rirekisho-field.md にある。 -->
```

## 記入例

```markdown
# 職務経歴書

2026年8月28日現在
氏名: {氏名}

## 職務要約

Python と Java によるバックエンド開発に8年間従事してきた。AWS 上の EC 基幹 API の設計・実装を軸に、決済基盤のマイクロサービス移行とリリース基盤の刷新を技術リードとして担当している。移行では、ピーク時 API 応答時間を平均820msから310msへ短縮（約62%改善）した。5名チームのマネジメントと採用面接も担い、設計と実装に自分で手を動かして関わる働き方を続けている。技術選定の裁量が大きい環境で、より上流の意思決定に関わりたいと考えている。

## 職務経歴

### 予約システムの API 実装（2023-04〜2026-06）

- 在籍企業: 架空ヘルスケアラボ株式会社
- 体制と役割: 業務委託（副業）／バックエンドエンジニア
- 担当
  - 予約システムの API 実装
- 成果
  - 予約枠の在庫計算をリアルタイム化: 予約確定までの待ち時間を平均12秒から2秒へ短縮
- 使用技術: Python、GCP

### リリース基盤の刷新（2023-01〜2023-12）

- 在籍企業: 架空リテールテック株式会社
- 体制と役割: バックエンドエンジニア / チームリード（5名チーム）
- 担当
  - リリースプロセスの CI/CD 整備
- 成果
  - リリースプロセスの CI/CD 整備: デプロイ頻度を週1回から日次へ（約5倍）、障害回復時間を平均4時間から40分へ短縮

### 決済基盤のマイクロサービス移行（2022-04〜2024-03）

- 在籍企業: 架空リテールテック株式会社
- 体制と役割: 技術リード（5名チーム）
- 担当
  - 決済基盤のマイクロサービス移行の技術リード
  - EC 基幹 API の設計・実装
- 成果
  - モノリスからマイクロサービスへの段階移行を主導: ピーク時 API 応答時間を平均820msから310msへ短縮（約62%改善）
- 使用技術: Python、AWS

### 業務システムの受託開発（2018-04〜2021-03）

- 在籍企業: 架空システムソリューションズ株式会社
- 体制と役割: ソフトウェアエンジニア
- 担当
  - 業務システムの受託開発
  - 顧客要件のヒアリングと基本設計
- 成果
  - 在庫管理バッチの処理最適化: 夜間バッチの実行時間を6時間から2.5時間へ短縮
- 使用技術: Java、Oracle

## テクニカルスキル

- 使用言語: Python、Java
- 環境・基盤: AWS（ECS, Lambda, RDS）、Terraform、Docker
- データベース: PostgreSQL

## 活かせる経験・知識・スキル

- 要件定義、アジャイル開発（スクラム）
- チームマネジメント、技術面接
- 課題の構造化と優先順位付け、チームメンバーへの傾聴とフィードバック

## 資格・免許

- 応用情報技術者
- AWS Certified Solutions Architect - Associate

## 自己PR

大規模移行を計画から完遂まで主導した実行力が強みです。決済基盤のモノリスからマイクロサービスへの段階移行では、2022年4月から2024年3月まで技術リードを務め、ピーク時 API 応答時間を平均820msから310msへ短縮（約62%改善）しています。並行してリリース基盤を刷新し、デプロイ頻度を週1回から日次へ（約5倍）、障害回復時間を平均4時間から40分へ短縮しました。移行の設計と実装に自分で手を動かして関わる働き方で、貢献いたします。
```
