# 職務経歴書テンプレート（キャリア式）

## 使い方

- 転職回数が多いとき、または分野をまたぐ経験を分野別に示したいときに選ぶ。時系列では経歴が断片的に見える場合に向く。
- 職務経歴は分野（またはプロジェクト）ごとに1ブロックとし、冒頭に時系列の職歴を簡潔に置く（出典 S5）。時系列一覧が無いと在籍の流れが読めなくなるため、省かない。
- 分量は、社会人経験7年程度まで A4 1〜2枚、それ以上は2〜3枚（出典 S8）。職務要約は200〜300字・3〜5行（出典 S2・S8）、自己PRは200〜400字（出典 S8）。
- `{profile.…}` は profile.json のフィールド、`{…}` は求人票・企業研究・作成日など profile.json 以外の入力を指す。`<!-- -->` は作成担当への指針であり、成果物には残さない。
- 値の無い項目を行ごと省くか「特になし」と書くかは、節ごとの `<!-- -->` に従う。
- 応募先が様式を指定した場合は、このテンプレートを使わず指定の様式に従う。

## 構成

```markdown
# 職務経歴書
<!-- 必須。表題を先頭に置き、続く2行の作成日と氏名を右寄せにする（出典 S2・S3・S6・S8）（Markdown では位置指定を付けず、Word・PDF へ書き出すときに整える）。氏名は profile.json に無いため利用者に確認する。日付は提出日とし、西暦・和暦は書類全体で統一する。 -->

{作成日}現在
氏名: {氏名}

## 職務要約
<!-- 必須。{profile.summary} を核に、{profile.basic.years_of_experience}・{profile.basic.current_role} と、後段で立てる分野の軸を200〜300字でまとめる。キャリア式では在籍の一貫性が読み取りにくいため、キャリアの軸をここで示す。{profile.career_gaps[]} がある場合、その説明はここか自己PRで用いる。節は省かない。 -->

## 職務経歴
<!-- 必須。冒頭に在籍企業の時系列一覧を置き、続けて分野ごとのブロックを並べる（出典 S5）。節は省かない。 -->

### 在籍企業（時系列）
<!-- 必須。{profile.career_history[]} を period の開始年月の古い順に、1社1行で並べる。事業内容・資本金・従業員数は、利用者が示した事実か企業研究の claim がある場合だけ社名の後に添え、無ければ書かない。創作しない。 -->

- {profile.career_history[].period} {profile.career_history[].company}（{profile.career_history[].role}）

### {分野名}
<!-- 必須。分野は {profile.career_history[].responsibilities[]} と {profile.career_history[].achievements[].project} をまとめ直して立て、{求人要件} に近い分野を先頭に置く。分野は3〜5個までとする。1つの実績を複数の分野へ重複して載せない。 -->

- 関与期間: {分野に対応する career_history[].period または achievements[].period}
- 在籍企業: {profile.career_history[].company}
<!-- どの分野がどの会社での経験かを必ず示す。示さないと在籍と経験の対応が読めなくなる。 -->
- 担当
  - {profile.career_history[].responsibilities[]}
- 実績
  - {profile.career_history[].achievements[].description}: {profile.career_history[].achievements[].metric}
<!-- metric は一字一句そのまま引く。丸め・水増しをしない。metric が null の実績には数値を付けず、担当範囲・役割・工夫を事実で書く。achievements が空の分野は「実績」の見出しごと省く。 -->

## 活かせる経験・知識・スキル
<!-- 推奨。{profile.skills.technical[]}・{profile.skills.business[]}・{profile.skills.portable[].skill} から、{求人要件} に対応するものだけを選ぶ。対応するものが無ければ節ごと省く。 -->

## 資格・免許
<!-- 必須。{profile.skills.certifications[]} を並べる。取得年月は profile.json に無いため、利用者が示した場合だけ添える。certifications が空なら「特になし」と書く。節は省かない。 -->

## 自己PR
<!-- 必須。{profile.strengths[]} から強みを1つ、多くて3つ選び、結論→証明→貢献の順で200〜400字（出典 S8）。分野をまたぐ経歴では、分野の間で一貫する軸を強みとして示す。詳しい構成は self-pr.md にある。節は省かない。 -->

## 志望動機・転職理由
<!-- 任意。応募先が求めた場合だけ置く。{profile.job_change_axis.reasons[]} と {company_research} の claim を素材に、200〜300字を目安とする。企業研究が無ければ企業固有の内容は書けないため、節ごと省く。詳しい構成は motivation-rirekisho-field.md にある。 -->
```

## 記入例

```markdown
# 職務経歴書

2026年8月28日現在
氏名: {氏名}

## 職務要約

業務システムの受託開発から EC 事業会社の内製開発まで、8年間バックエンドの設計・実装に携わってきた。分野は、基幹 API の設計・実装、システム基盤の刷新、チーム運営の3つである。いずれの分野でも、定量指標で効果を示すデータ志向の改善を強みとしてきた。直近では決済基盤のマイクロサービス移行を主導し、ピーク時 API 応答時間を平均820msから310msへ短縮（約62%改善）している。技術選定の裁量が大きい環境で、より上流の意思決定に関わりたいと考えている。

## 職務経歴

### 在籍企業（時系列）

- 2018-04〜2021-03 架空システムソリューションズ株式会社（ソフトウェアエンジニア）
- 2021-10〜2026-06 架空リテールテック株式会社（バックエンドエンジニア / チームリード）
- 2023-04〜2026-06 架空ヘルスケアラボ株式会社（業務委託（副業）／バックエンドエンジニア）

### バックエンド API の設計・実装

- 関与期間: 2018-04〜2021-03、2021-10〜2026-06
- 在籍企業: 架空システムソリューションズ株式会社、架空リテールテック株式会社、架空ヘルスケアラボ株式会社
- 担当
  - 業務システムの受託開発（Java, Oracle）と、顧客要件のヒアリングおよび基本設計
  - EC 基幹 API の設計・実装（Python, AWS）
  - 予約システムの API 実装（Python, GCP）
- 実績
  - 予約枠の在庫計算をリアルタイム化: 予約確定までの待ち時間を平均12秒から2秒へ短縮
  - 在庫管理バッチの処理最適化: 夜間バッチの実行時間を6時間から2.5時間へ短縮

### システム基盤の刷新

- 関与期間: 2022-04〜2024-03
- 在籍企業: 架空リテールテック株式会社
- 担当
  - 決済基盤のマイクロサービス移行の技術リード
- 実績
  - モノリスからマイクロサービスへの段階移行を主導（2022-04〜2024-03）: ピーク時 API 応答時間を平均820msから310msへ短縮（約62%改善）
  - リリースプロセスの CI/CD 整備（2023-01〜2023-12）: デプロイ頻度を週1回から日次へ（約5倍）、障害回復時間を平均4時間から40分へ短縮

### チーム運営と採用

- 関与期間: 2021-10〜2026-06
- 在籍企業: 架空リテールテック株式会社
- 担当
  - 5名チームのマネジメントと採用面接

## 活かせる経験・知識・スキル

- バックエンド開発: Python、Java、PostgreSQL
- クラウドと基盤: AWS（ECS, Lambda, RDS）、Terraform、Docker
- 開発の進め方: 要件定義、アジャイル開発（スクラム）、課題の構造化と優先順位付け
- チーム運営: チームマネジメント、技術面接

## 資格・免許

- 応用情報技術者
- AWS Certified Solutions Architect - Associate

## 自己PR

分野が変わっても、定量指標で効果を示すデータ志向の改善という軸は変わりません。受託開発では在庫管理バッチの処理を最適化し、夜間バッチの実行時間を6時間から2.5時間へ短縮しています。EC 事業会社では決済基盤の段階移行を主導し、ピーク時 API 応答時間を平均820msから310msへ短縮しました（約62%改善）。リリース基盤の刷新では、デプロイ頻度を週1回から日次へ（約5倍）改善しています。5名のチームではマネジメントと採用面接も担当しました。分野を移っても再現できるこの軸で、貢献いたします。
```
