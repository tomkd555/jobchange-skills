# 履歴書テンプレート（従来様式・旧 JIS 相当）

## 使い方

- 応募先が、配偶者・扶養家族・通勤時間欄のある様式を指定したときだけ選ぶ（出典 R29）。指定がなければ `rirekisho-mhlw.md` を使う。
- 厚労省様式例との違いは、通勤時間・扶養家族数（配偶者を除く）・配偶者・配偶者の扶養義務の4欄がある点だけである。他の項目と記入規則は厚労省様式例と同じとする。
- 性別は任意記載欄とし、男・女の選択にしない（出典 R24・R26・R28）。応募先の指定様式が選択式であっても、未記載のまま提出してよい。
- 志望の動機欄は200〜300字とする（出典 M1・M2）。書き出しを約100字、中間を60〜100字、締めを60〜100字とする（出典 M2）。
- `{profile.…}` は profile.json のフィールド、`{…}` は求人票・企業研究・作成日など profile.json 以外の入力を指す。`<!-- -->` は作成担当への指針であり、成果物には残さない。
- 職歴の空白期間は履歴書に書かない。`{profile.career_gaps[]}` の説明は職務経歴書の職務要約か自己PRで用いる。

## 構成

```markdown
# 履歴書

{作成日}現在
<!-- 必須。提出日を書く。郵送する場合は投函日とする。西暦と和暦のどちらを使うかは書類全体で統一する（出典 R9・R14・R21）。 -->

| 項目 | 記入欄 |
|---|---|
| ふりがな | {ふりがな} |
| 氏名 | {氏名} |

| 性別（任意記載） | {性別} |
| 写真 | {写真の貼付} |
<!-- ふりがな・氏名は必須。profile.json に無いため利用者に確認する。見出しが「ふりがな」ならひらがな、「フリガナ」ならカタカナで書く（出典 R14）。 -->
<!-- 生年月日は必須。性別は任意記載欄であり、利用者が記載を望まなければ空欄のままとする。男・女の選択肢を書かない（出典 R24・R26・R28）。 -->
<!-- 写真は任意（出典 R25）。貼る場合は縦4cm×横3cm、3か月以内の撮影とする（出典 R9・R13・R14・R21）。貼らない場合は行ごと省く。 -->

| 項目 | 記入欄 |
|---|---|
| ふりがな | {現住所のふりがな} |
| 現住所 | 〒{郵便番号} {現住所} |
| 電話 | {電話番号} |
| E-mail | {メールアドレス} |
| 連絡先 | {連絡先} |
<!-- 現住所・電話・E-mail は必須。現住所は {profile.basic.location} を含む形で、都道府県から省略せずに書く（出典 R14）。番地・建物名は profile.json に無いため利用者に確認する。 -->
<!-- 連絡先は任意。現住所と異なる場合だけ書き、同じなら行ごと省く（出典 R14）。 -->

## 学歴・職歴
<!-- 必須。学歴と職歴を各別にまとめ、それぞれの先頭に「学歴」「職歴」の行を置く（出典 R13・R15）。最終行の「以上」は右寄せにする（出典 R9・R15・R21）（Markdown では位置指定を付けず、Word・PDF へ書き出すときに整える）。 -->

| 年 | 月 | 学歴・職歴 |
|---|---|---|
|  |  | 学歴 |
| {年} | {月} | {高等学校名} 卒業 |
| {年} | {月} | {profile.basic.education[]} 入学 |
| {年} | {月} | {profile.basic.education[]} 卒業 |
|  |  | 職歴 |
| {年} | {月} | {profile.career_history[].company} 入社 |
| {年} | {月} | 一身上の都合により退職 |
|  |  | 以上 |
<!-- 学歴は、最終学歴が高校卒業以上なら「◯◯高等学校 卒業」から書き始める（出典 R13・R21）。高等学校名と入学年月は profile.json に無いため利用者に確認する。education の卒業年月はそのまま使う。 -->
<!-- 職歴は古い順に、社名を正式名称で書く（出典 R13）。退職は「一身上の都合により退職」か「会社都合により退職」とする（出典 R15・R21）。 -->
<!-- 在職中は「現在に至る」と書く。退職日が確定していれば「現在に至る（◯年◯月◯日退職予定）」とする（出典 R15）。 -->
<!-- 業務委託・副業として就業した会社の扱いは、記載するかどうかを利用者に確認する。記載する場合も「入社」「退職」ではなく契約の開始・終了として書く。在学中のアルバイト・派遣就業（profile.json の employment_type に記録がある）は、利用者が記載を望まない限り履歴書には書かない。この記入例でも省いている。 -->
<!-- 職歴の空白期間は書かない。空白の説明は職務経歴書の職務要約か自己PRで扱う。 -->

## 免許・資格
<!-- 必須。{profile.skills.certifications[]} を取得年月とともに正式名称で書く。取得年月は profile.json に無いため利用者に確認し、確認できなければ資格名だけを書く。certifications が空なら「特になし」と書く。節は省かない。 -->

| 年 | 月 | 免許・資格 |
|---|---|---|
| {年} | {月} | {profile.skills.certifications[]} |

## 志望の動機、特技、好きな学科、アピールポイントなど
<!-- 必須。200〜300字（出典 M1・M2）。書き出しで貴社を志望する結論を述べ、{profile.career_history[].achievements[]} の事実で裏づけ、入社後の貢献で締める。企業側の要素は {company_research} の claim を根拠にする。企業研究が無い場合は企業固有の記述を避け、{axis.job_change_axis.reasons[]} に基づく汎用の内容に留める。詳しい構成は motivation-rirekisho-field.md にある。 -->

## 通勤時間・扶養家族・配偶者

| 項目 | 記入欄 |
|---|---|
| 通勤時間 | 約{時間}時間{分}分 |
| 扶養家族数（配偶者を除く） | {人数}人 |
| 配偶者 | {有／無} |
| 配偶者の扶養義務 | {有／無} |
<!-- この4欄は従来様式だけに置く。厚労省様式例には無い（出典 R3）。応募先がこの様式を指定した場合にのみ書く。 -->
<!-- いずれも profile.json に無い。利用者に確認して書き、確認できない欄は空欄のままとする。推測で埋めない。 -->
<!-- 通勤時間は応募先の勤務地から自宅までの片道の所要時間を書く。勤務地が定まらない場合は空欄のままとする。 -->
<!-- 扶養家族数は配偶者を除いた人数、配偶者の扶養義務は配偶者を扶養しているかを指す（出典 R18）。 -->

## 本人希望記入欄
<!-- 必須。希望が無ければ「貴社規定に従います」と書く（出典 R17・R21・R22）。「特になし」・空欄・待遇の具体額は書かない（出典 R17・R22）。勤務地や勤務時間に外せない事情がある場合だけ、その事情を1〜2行で書く。 -->
```

## 志望の動機、特技、好きな学科、アピールポイントなど

貴社を志望する理由は、使う言語とクラウド構成を開発チーム自身が決められる体制と、その判断の過程を技術ブログで公開している姿勢にあります。技術選定の裁量が大きい環境で、より上流の意思決定に関わりたいと考えてきました。前職では決済基盤のマイクロサービス移行を技術リードとして担い、ピーク時 API 応答時間を平均820msから310msへ短縮（約62%改善）しています。移行と CI/CD 整備で身につけた、現状の計測から改善の順序を決める進め方を、貴社の基幹システムの拡張に活かし、開発チームの意思決定に貢献いたします。
