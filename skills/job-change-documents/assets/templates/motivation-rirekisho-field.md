# 志望動機テンプレート（履歴書の志望動機欄）

## 使い方

- 履歴書または職務経歴書の志望動機欄に書く場合に選ぶ。応募先が志望動機書（A4 1枚）の提出を求めた場合は `motivation-letter.md` を使う。
- 分量は200〜300字（出典 M1・M2）。内訳は書き出し約100字、中間60〜100字、締め60〜100字（出典 M2）。職務経歴書の志望動機欄の字数を定めた出典は無いため、同じ構成と分量を目安として用いる。
- 書き出しは、M1 が示す「貴社を志望する理由は」で始まる型を用い、企業に向けた結論から述べる。「私は○○に携わりたい」型は自分に向いた文になるため用いない。
- 3段は続けて1つの文章として書き、見出しを成果物に残さない。応募先へ向けた文章であるため敬体で書く。
- `{profile.…}` は profile.json のフィールド、`{…}` は求人票・企業研究など profile.json 以外の入力を指す。`<!-- -->` は作成担当への指針であり、成果物には残さない。
- 書かないこと: 待遇・勤務条件を主な理由にする、前職への不満、他社にも通じる社風賛美、「学ばせていただく」型の受け身、「頑張ります」だけの意欲（出典 M1・M2・M6・M11・M14）。

## 構成

```markdown
<!-- 必須。3段を続けて1つの文章として書く。以下の3つの見出しは構成を示すためのものであり、成果物には残さない。 -->

【書き出し（結論）】約100字
<!-- 必須。「貴社を志望する理由は」で始まる型を用い、その企業を選ぶ理由を先に述べる（出典 M1）。理由には {company_research} の claim（理念・事業・求める人物像）から、その企業に固有の要素を置く。競合他社にも当てはまる内容にしない。企業研究が無い場合は企業固有の記述を避け、{profile.job_change_axis.reasons[]} に基づく汎用の内容に留め、企業研究の後に書き直す旨を利用者へ伝える。 -->

【根拠となるエピソード】60〜100字
<!-- 必須。結論を裏づける自分の経験を、{profile.career_history[].achievements[]} から1件選んで書く。数値は {profile.career_history[].achievements[].metric} を一字一句そのまま引く。丸め・水増しをしない。metric が null の実績を選んだ場合は数値を付けず、担当範囲と工夫を事実で書く。{profile.job_change_axis.reasons[]} と食い違う理由を書かない。 -->

【締めくくり（入社後の貢献）】60〜100字
<!-- 必須。前段の経験を応募先で何にどう活かすかを述べる。{求人要件} に対応づける。求人票が無い場合は {company_research} の事業内容に対応づける。「頑張ります」だけの意欲で終わらせない。 -->
```

## 記入例

```markdown
貴社を志望する理由は、使う言語とクラウド構成を開発チーム自身が決められる体制であり、その判断の過程を技術ブログで公開されているからです。技術選定の裁量が大きい環境で、より上流の意思決定に関わりたいと考えてきました。前職では決済基盤のモノリスからマイクロサービスへの段階移行を主導し、ピーク時 API 応答時間を平均820msから310msへ短縮（約62%改善）しています。この移行で身につけた、現状の計測から改善の順序を決める進め方を、貴社の決済プロダクトの拡張に活かし、開発チームの技術選定に貢献いたします。
```

<!-- 記入例の企業は架空クラウドワークス社を想定している。企業側の要素（技術選定の体制・技術ブログ）は、実際の作成では対象企業の company_research.json の claim を根拠とする。 -->
